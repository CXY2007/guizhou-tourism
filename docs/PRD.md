## 1. 项目概述

一个以**贵州**为目的地的文旅网站，用沉浸式大图叙事呈现 18 个景点，提供搜索、收藏、评论、评分、天气与出行建议、多日行程规划、AI 旅行助手，以及三级权限（游客 / 登录用户 / 管理员）和后台内容管理。

- 性质：课程作业，1–2 周交付，本地演示为主
- 技术栈：Flask 3 + Jinja2 + Tailwind CSS + Alpine.js + SQLAlchemy + MySQL 8
- 设计方向：沉浸式大图叙事（墨绿 / 石青 / 朱砂 / 米白 / 金）

## 2. 目标用户与场景

| 用户 | 场景 | 核心诉求 |
|---|---|---|
| 行前游客 | 还没决定去哪，刷首页找灵感 | 好看、可信、能快速判断“值不值得去” |
| 计划游客 | 已锁定几个景点，想排行程 | 看详情、比门票/时长、生成多日行程 |
| 到地游客 | 已在贵州，关心天气与交通 | 天气、出行建议、附近吃住、路线 |
| 内容管理员 | 维护景点与评论 | 快速录入、审核、上下架 |

## 3. 产品目标与非目标

**目标**
1. 首页 10 秒内建立“贵州山水”的视觉印象。
2. 18 个景点信息完整、可搜索、可筛选、可收藏。
3. 游客能在一屏内看懂：在哪、多少钱、玩多久、什么时候去最好。
4. AI 小球能用一句话把用户带到正确页面（导航型意图准确率 ≥ 90%）。
5. 三级权限真实生效，后台能独立完成内容维护。

**非目标（本期不做）**
- 真实支付与对账（预订只做演示级：下单 → 模拟支付成功）
- 实时库存、真实房价/票价接口
- 复杂推荐算法（用规则 + 标签）
- UGC 自动审核（管理员人工审核）
- 多语言超过中/英两种

## 4. 角色与权限

| 能力 | 游客 | 登录用户 | 管理员 |
|---|---|---|---|
| 浏览首页/列表/详情/线路/搜索 | ✅ | ✅ | ✅ |
| 使用 AI 小球（问答/跳转/行程建议） | ✅ | ✅ | ✅ |
| 收藏 / 取消收藏 | ❌（引导登录） | ✅ | ✅ |
| 评论 / 评分 | ❌（引导登录） | ✅ | ✅ |
| 修改密码 / 个人资料 | ❌ | ✅ | ✅ |
| 创建/保存行程 | ❌ | ✅ | ✅ |
| 预订（演示） | ❌ | ✅ | ✅ |
| 进入 `/admin` | ❌ | ❌ | ✅ |
| 景点 CRUD / 上下架 | ❌ | ❌ | ✅ |
| 评论审核 / 删除 | ❌ | ❌ | ✅ |
| 用户与角色管理 | ❌ | ❌ | ✅ |
| 订单查看 | ❌ | 仅自己 | 全部 |

未登录访问受限操作：JSON API 返回 401 + 统一包裹 `{"ok":false,"data":null,"error":{"code":"login_required"}}`；页面路由重定向到 `/login?next=<当前页>`。前端弹层登录引导，登录后回到原页面。

## 5. 功能范围与优先级

### P0（必须，答辩前完成）
1. 首页沉浸式叙事（5 屏滚动 + 推荐）
2. 景点列表（分类筛选、排序、分页）
3. 景点详情（图集轮播、地图、天气、评分、评论、AI 建议、预订入口）
4. 搜索（关键词 + 分类）
5. 用户系统（注册/登录/退出/改密）
6. 三级权限与后台入口保护
7. 收藏 / 评论 / 评分
8. AI 小球（问答 + 页面跳转 + 行程建议）
9. 18 景点数据（中英摘要、≥4 图、坐标、票价、时长、最佳月份）
10. 天气与出行建议（和风 API，失败走兜底）
11. 后台：景点 CRUD、评论审核、订单列表

### P1（应该有）
12. 主题线路（红色 / 自然 / 亲子 / 摄影）
13. 多日行程规划（选景点 + 天数 → 日程）
14. 预订演示（日期/人数 → 订单 → 模拟支付）
15. 中英双语切换

### P2（可选）
16. 评分数据看板（饼图 + 周趋势）
17. 分享卡片 / SEO meta
18. 管理员操作日志

## 6. 关键用户故事

1. 作为游客，我打开首页就能看到贵州的山水与推荐景点，不用登录。
2. 作为游客，我搜索“瀑布”，能看到黄果树等结果并按分类筛选。
3. 作为游客，我在详情页看到门票、时长、最佳月份、地图和天气，决定是否收藏；点收藏时被引导登录。
4. 作为登录用户，我对景点打分并写评论，评论进入待审状态。
5. 作为登录用户，我选 3 个景点和 3 天，得到一份按天划分的行程，可保存。
6. 作为登录用户，我预订某景点某天的门票，生成订单并模拟支付成功。
7. 作为游客，我对 AI 小球说“带我去黄果树”，它直接跳到黄果树详情页。
8. 作为管理员，我新增一个景点、上传图片、发布上线，前台立即可见。

## 7. 验收标准

| # | 标准 |
|---|---|
| 1 | 18 景点数据完整：中英摘要、≥4 图、坐标、票价、开放时间、建议时长、最佳月份 |
| 2 | 三级权限逐条可演示：游客收藏被拒、用户进后台被拒、管理员全通 |
| 3 | AI 小球 7 类意图中至少 6 类可用，导航型意图准确率 ≥ 90%，P95 < 3s |
| 4 | 375 / 768 / 1440 三档无横向滚动、无文字溢出 |
| 5 | Lighthouse 移动端性能 ≥ 85、可访问性 ≥ 90 |
| 6 | `pytest` 冒烟通过；无明文密钥进入仓库 |
| 7 | 后台完成“新增景点 → 前台可见”的完整闭环 |

## 8. 约束与依赖

- 运行环境：本机 Windows + Python 3.13 + MySQL 8，演示端口 8899
- 外部服务：高德地图（Web/JS key）、和风天气、LLM（站点 AI）
- 数据：现有 8 个景点保留，新增 10 个；图片需确认版权
- 时间：1–2 周；D1 冻结、D2–D6 施工、D7 验收
- Agent 分工：DSH 指挥 / Claude Code 前端 / Codex 后端 / 双模型审核

## 9. 风险

| 风险 | 影响 | 对策 |
|---|---|---|
| DashScope 429 | 站点 AI 不可用 | 换 key 或改 DeepSeek，接口层可切换 |
| 新景点资料少（花江峡谷大桥） | 内容失真 | 官方/新闻多源交叉，缺证据标 TBD |
| 季节型景点花期过期 | 信息错误 | 标注“以官方公告为准”，后台可改 |
| 图片版权 | 无法公开演示 | 自有/免费图库/AI 示意图并标注 |
| 1–2 周工期 | 功能做不完 | P0 优先，P1 可砍，P2 不做 |
