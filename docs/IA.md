## 3. 关键用户流程

### 3.1 浏览 → 详情 → 收藏/评分
```
首页/列表 → 详情页 → 点收藏
  ├─ 未登录 → 弹层“登录后收藏” → 登录 → 回到详情页并完成收藏
  └─ 已登录 → 收藏成功（按钮态变化）
详情页 → 打星 → 平均分即时更新
详情页 → 写评论 → 提交 → 提示“待审核”
```

### 3.2 搜索
```
任意页顶部搜索框 → /search?q=瀑布
  → 结果列表（可切分类）→ 详情
  → 无结果：空态 + 推荐热门景点
```

### 3.3 行程规划
```
/itinerary → 选景点（≥2）→ 选天数（1–5）→ 生成
  → 服务端 `POST /api/itinerary/generate`（**游客可用**，不落库）
  → 按天分组的日程（上午/下午/晚上）
  → 未登录：可看不可存；登录：`POST /api/itineraries` 保存到 /profile
  → AI 小球可带 `attraction_ids[]` 与 `days` 预填本页
```

### 3.4 预订（演示）
```
详情页“预订” → /booking/<attraction_id>（参数是景点 ID）→ 选日期/人数 → 计算金额
  → 提交订单（pending，返回 booking_id）→ 模拟支付（按 booking_id）
  → paid → 跳 /orders 可见；管理员 /admin/orders 可见
```

### 3.5 后台录入
```
/admin/attractions → 新增 → 填字段/上传图 → 保存为 draft
  → 发布 → 前台列表可见
```

## 5. AI 小球交互规范

### 5.1 入口与形态
- 悬浮按钮（56–64px），点击展开 360×520 面板；移动端全宽底部抽屉
- 开场白：一句欢迎 + 3 个建议问题（“帮我安排 3 天”“现在去哪最好”“黄果树怎么去”）

### 5.2 意图与动作

| 意图 | 触发示例 | 动作 |
|---|---|---|
| `navigate` | “带我去黄果树”“打开我的收藏” | 跳转对应路由 |
| `search` | “找瀑布”“红色景点” | 跳 `/search?q=` 或 `/attractions?category=` |
| `itinerary` | “排 3 天行程” | 跳 `/itinerary`，带上景点参数 |
| `qa` | “门票多少”“玩多久” | 基于景点数据回答 |
| `weather` | “明天下雨吗” | 返回天气 + 出行建议 |
| `booking` | “怎么买票” | 跳详情页或 `/booking/<id>` |
| `help` | “你能做什么” | 返回能力说明 |

### 5.3 响应契约
```json
{
  "reply": "黄果树瀑布在安顺，门票 160 元，建议玩 4–6 小时。",
  "action": { "type": "navigate", "url": "/attractions/huangguoshu" },
  "confidence": 0.92
}
```
- `action` 可为 `null`；前端只在 `type` 合法且 URL 属于站内白名单时执行跳转。
- 超时/失败：返回兜底话术 + 3 个建议问题，不阻断页面。

### 5.4 约束
- 不回答与贵州文旅无关的问题，统一引导回站点能力。
- 不输出用户隐私；不执行站外链接。
- P95 延迟 < 3s；失败重试 1 次后兜底。

## 6. 内容模型（页面视角）

每个景点在页面上呈现四层信息：
1. **决策层**：名称、一句话卖点、票价、建议时长、最佳月份、分类
2. **感受层**：主图/图集、诗意描述
3. **事实层**：地址、坐标、开放时间、交通、贴士
4. **互动层**：评分、评论、收藏、预订、AI 建议

## 7. 状态与空态

| 场景 | 处理 |
|---|---|
| 搜索无结果 | 空态插画 + “换个关键词” + 热门推荐 |
| 未登录做受限操作 | 弹层登录引导，不跳页 |
| 评论待审 | 提示“已提交，审核后展示” |
| 天气服务失败 | 展示“天气暂不可用”，不阻塞详情页 |
| AI 失败 | 兜底话术 + 建议问题 |
| 图片缺失 | 占位图 + 景点名首字 |
